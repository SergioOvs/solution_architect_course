# Обоснование и объяснение выбранного подхода к пагинации и версионированию API
## Пагинация: offset-based (limit + offset)
Для endpoint /appointments выбран offset-based подход к пагинации с параметрами limit и offset. 
Это решение обусловлено несколькими причинами:
1. **_Простота реализации и поддержка на стороне клиента_**<br>Мобильные разработчики привыкли к offset-пагинации: 
она интуитивно понятна, легко интегрируется с UI-библиотеками (RecyclerView, UITableView) и не требует хранения 
курсоров или токенов на стороне клиента.
2. **_Совместимость с существующими системами_**<br>В большинстве реляционных СУБД (PostgreSQL, MySQL) и 
ORM (SQLAlchemy, Hibernate) offset-пагинация реализуется стандартными средствами (LIMIT/OFFSET), что снижает порог 
внедрения и не требует доработки legacy-слоёв.
3. **_Прозрачность для пользователя_**<br>Параметры limit и offset явно видны в URL, что упрощает отладку, кэширование и
логирование. Клиент всегда знает, какую "страницу" он запрашивает.
4. **_Контроль нагрузки_**<br>Ограничение limit (максимум 100) защищает backend от перегрузки и предотвращает
неэффективные запросы с большими смещениями. При необходимости можно добавить кэширование или переход 
на keyset-пагинацию для особо крупных выборок.

## Версионирование: версия в URL (/api/v1/...)
Для версионирования API выбран подход с явным указанием версии в URL (/api/v1/...). 
Это решение обосновано следующими факторами:
1. **_Прозрачность и явность_**<br>Версия сразу видна в адресе запроса, что упрощает диагностику, мониторинг и кэширование 
на стороне CDN или gateway. Клиент и сервер однозначно понимают, какой контракт используется.
2. **_Простота поддержки нескольких версий_**<br>Подход позволяет параллельно эксплуатировать несколько версий API 
(например, /v1/ и /v2/), что критично для мобильных приложений с долгим циклом обновления.
3. **_Совместимость с инфраструктурой_**<br>Версия в URL легко маршрутизируется на уровне API Gateway, load balancer или ingress,
не требуя сложной логики на уровне приложения.
4. **_Соответствие практикам_**<br>Такой подход широко используется в крупных публичных и внутренних API 
(GitHub, Google), что делает его привычным для разработчиков и снижает порог входа.
