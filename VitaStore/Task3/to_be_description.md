# HLD для Vita Store
## Переход от «толстого» клиента к cloud‑native решению 
Вместо монолита POS App (Windows/C#) с жёстко встроенными драйверами оборудования вводится Web POS App. Это лёгкое 
приложение для планшета или браузера. Оно не содержит драйверов и бизнес‑логики — всё это вынесено в микросервисы 
облачного бэкенда (Cloud Backend). Благодаря этому магазин избавляется от локального сервера БД (MS SQL Express) и 
зависимости от Windows‑кассовых станций.

## Решение проблемы разнообразного местного «железа» 
Для работы с разнородным оборудованием магазинов создаётся прослойка HAL Edge Device Bridge. Она устанавливается 
непосредственно в магазине и предоставляет унифицированный REST API для кассы. Внутри HAL реализованы отдельные 
адаптеры: Payment Terminal Adapter, Fiscal Printer Adapter. Эти адаптеры содержат специфические драйверы под разные 
модели терминалов и принтеров. Таким образом, Web POS общается только со стандартным интерфейсом HAL, а не напрямую 
с железом. При покупке нового магазина достаточно добавить новый адаптер в HAL, не меняя код кассовой программы.

## Обеспечение работы при обрыве связи (Offline‑mode strategy)
Магазин продолжает работать офлайн благодаря зоне OFFLINE‑CAPABLE ZONE. В ней функционирует:
* <b><i>Offline Cache:</i></b> кеширует актуальные данные о товарах из облака. Позволяет обслуживать покупателей 
за наличный расчёт без обращения к интернету.
* <b><i>HAL Edge Device Bridge:</i></b> принимает чеки от кассы, отправляет их на печать через драйвер адаптера 
и сохраняет цифровые копии чеков во внутренней базе данных до восстановления связи.

Как только связь восстанавливается, HAL инициирует пакетную синхронизацию накопленных чеков по HTTPS в облако. Облако 
проверяет целостность транзакций с помощью событийной модели (Event Sourcing) и двухфазной фиксации. Если штрихкод 
товара не найден в SAP ERP, чек помечается как требующий ручной проверки товароведом HQ.
