# Task 1. Архитектурная диагностика и целевое видение AdScale
Директория: Solution-AdScale/Task1

## Цель
Проведение архитектурной диагностики с подготовкой документации для текущего состояния AdScale, а также разработка и 
документирование развития системы до целевой архитектуры в горизонте 1 года

Ключевой бизнес-драйвер: подключение новой DSP-платформы с повышением нагрузки на 20% на производительность и выполнению
SLA 99.9% без деградаций системы.

## Состав артефактов
1. ADR - директория, в которой хранятся ADR  
   1. `ADR-001.md` - ADR-001: Стратегия эволюции архитектуры (от монолита к микросервисам)
   2. `ADR-002.md` - ADR-002: Выделение сервиса ставок в качестве первого приоритета

5. `TO-BE.md` - описание целевой архитектуры

## Краткий обзор
Текущее состояние архитектуры - гибридный монолит с единой PostgreSQL(1 инстанция), у которой отсутствуют кэш, очереди,
контейнеризация, автоматизированный deploy/rollback. Источниками основных рисков являются следующие факторы:
* hot path RTB-аукциона
* прямое взаимодействие всех сервисов с единой production БД
* конкуренция за ресурсы между аналитическими запросами и транзакционными операциями

Целевое решение - переход из монолита в микросервисную архитектуру используя Strangler Fig Pattern. Основные шаги:
* Выделение потоков ставок, событий и чтения кампаний как наиболее критичных
* Выделение данных по сервисам
* Добавление API Gateway, кэширования (Redis), очередей (Kafka) и observability
* Горизонтальное масштабирование
